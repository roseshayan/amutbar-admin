# سازگاری احراز هویت با API.ir

قرارداد در ۲۰ سپتامبر ۲۰۲۶ با [OpenAPI رسمی](https://s.api.ir/json)، [مستندات](https://s.api.ir/scalar/v1) و [SDK رسمی PHP](https://github.com/api-ir/php-sdk/tree/c4f5d2ed8eafa4cce43205abfe4c411f9206d5a4) تطبیق داده شد. کلاینت داخلی پروژه حفظ شده است؛ SDK جدید به وابستگی‌ها اضافه نشده است.

## تغییرات

- مبدا درخواست‌ها `https://s.api.ir` و احراز دسترسی `Authorization: Bearer` است. کلید از Bearer Token و در صورت خالی بودن از API Key پنل خوانده می‌شود.
- شاهکار از `ShahkarLite` استفاده می‌کند؛ پاسخ false تطبیق‌نداشتن هویت است، نه قطع سرویس.
- `PersonImage` در قرارداد فعلی وجود ندارد. مسیرهای اپ از `PersonData` با کد ملی و تاریخ تولد استفاده می‌کنند. تعریف قدیمی سرویس در پنل نیز به این مسیر نگاشت می‌شود. تصویر ممکن است در پاسخ موجود نباشد.
- کلید قدیمی تنظیم `require_national_serial` برای حفظ سازگاری، همچنان کنترل استعلام مشخصات/تصویر است. الزام ورود سریال در متادیتای اپ از فعال‌بودن ویدئو تعیین می‌شود.
- `VideoVerify` به سریال کارت یا کد رهگیری، تاریخ تولد، ویدئو و متن خوانده‌شده نیاز دارد. متن از `VideoVerifySpeechText` گرفته می‌شود؛ قالب جملهٔ ثابت پنل دیگر استفاده نمی‌شود.
- متن ضبط در سرور به کاربر و نقش اپ متصل است؛ ۱۰ دقیقه اعتبار دارد و فقط یک بار قابل ارسال است. پس از خطا یا انقضا باید متن جدید دریافت و ویدئوی جدید ضبط شود. درخواست متن خودکار انجام نمی‌شود.
- سقف فایل نهایی ویدئو ۵ مگابایت است. نتیجه فقط با true بودن `isPassed`، `isMatch`، `isLiveness` و `isSpeechMatched` تأیید می‌شود.
- حداقل timeout سرویس سبک ۳۰، مشخصات/تصویر ۶۰ و ویدئو ۱۲۰ ثانیه است. درخواست هزینه‌دار به طور خودکار تکرار نمی‌شود؛ timeout ممکن است پس از کسر اعتبار رخ دهد.

## مدیریت خطا

خطاهای شبکه، TLS، timeout، JSON نامعتبر، دسترسی کلید، محدودیت نرخ و خطای سرویس پیام فارسی و کد ساختاریافته دارند. خطای دسترسی ارائه‌دهنده به 503 تبدیل می‌شود تا اپ آن را با انقضای ورود کاربر اشتباه نگیرد. پیام خام ارائه‌دهنده نمایش داده نمی‌شود. شناسهٔ پیگیری خطاهای ارائه‌دهنده در پاسخ و لاگ مشترک است؛ محتوای هویتی، ویدئو و کلید در لاگ درخواست ذخیره نمی‌شوند.

اپ‌ها پاسخ `ok:false` حتی با HTTP 200 را خطا می‌دانند و در خطای موقت سرور نشست را حفظ می‌کنند. `retryable` صرفاً راهنمای تلاش دستی است و باعث استعلام خودکار نمی‌شود.

## انتشار

1. روی دیتابیس موجود، فایل `database/migrations/2026_09_20_000007_video_verification_challenges.sql` را یک‌بار ایمپورت کنید؛ اجرای مجدد آن امن است. نصب جدید جدول را در `schema.sql` دارد.
2. بک‌اند و نسخهٔ جدید هر دو اپ را هماهنگ منتشر کنید. اپ قدیمی بدون `challenge_token` نمی‌تواند ویدئو را تأیید کند؛ در پنل نسخهٔ حداقل اپ را متناسب با نسخهٔ منتشرشده تنظیم کنید.
3. سرویس فعال VideoVerify باید برای نقش مربوطه یا همهٔ نقش‌ها تعریف شده باشد. کلید معتبر، اعتبار و مجوز/IP سرویس را در حساب API.ir بررسی کنید.
4. timeout وب‌سرور و PHP-FPM برای پردازش ویدئو کافی باشد (مثلاً ۲۴۰ ثانیه). برای فایل خام ۱۵MB، `upload_max_filesize` حداقل 15M و `post_max_size` بزرگ‌تر از آن باشد. ffmpeg اختیاری است؛ بدون آن فایل باید از ابتدا زیر سقف نهایی باشد.
5. پس از استقرار، روی گوشی واقعی هر دو نقش، ضبط صدا و تصویر و یک استعلام مجاز واقعی را بررسی کنید. آزمون‌های خودکار شبکهٔ ارائه‌دهنده و حساب تجاری را تأیید نمی‌کنند.

## آزمون‌ها

```powershell
php tests/api_ir_contract.php
php tests/verification_controls.php
```

هر آزمون دیتابیس موقت دارد. اولی شامل ۶۰ بررسی حساب مشترک و ۵۱ بررسی قرارداد/خطا و متن یک‌بارمصرف است؛ دومی شامل همان ۶۰ بررسی و ۲۲ بررسی کنترل احراز هویت است. هیچ استعلام هزینه‌داری انجام نمی‌شود.

در هر اپ: `flutter test --no-pub`، شامل آزمون رابط راهنما و مدیریت خطاهای API.

## اجرای دستی از ویرایش کاربر

فهرست سرویس‌ها هنگام خواندن با قرارداد فعلی هماهنگ می‌شود؛ نیاز به اصلاح دستی ردیف‌های قدیمی دیتابیس نیست. PersonImage به PersonData تبدیل و Shahkar2 و VideoMatch غیرفعال نمایش داده می‌شوند. نقش اپ باید متعلق به کاربر باشد. استعلام دوبارهٔ ویدئو فقط روی آخرین ضبط دارای متن اصلی و نقش همان اپ اجرا می‌شود؛ فایل‌های قدیمی بدون متن معتبر باید در اپ دوباره ضبط شوند. اجرای استعلام به‌تنهایی وضعیت تأیید دستی پروفایل راننده/اعلام بار را تغییر نمی‌دهد.
